# rdv on the web

Examples of [rdv](https://github.com/rendervous/rdv_project) megakernels running in the browser through WebGPU.

Live: https://rendervous.github.io/rdv_on_the_web/

| Example | |
|---|---|
| [Volume transmittance](https://rendervous.github.io/rdv_on_the_web/transmittance/) | Ray-marched transmittance through a heterogeneous volume. Left drag orbits, right/Shift drag pans, scroll zooms; evaluate/draw times are shown live. |
| [Volume radiance](https://rendervous.github.io/rdv_on_the_web/radiance/) | Unbiased path tracing (delta tracking + next-event estimation, `PBVR_NEE`) of the same volume lit by a single directional light, accumulated progressively. Same camera controls, plus light/medium sliders. |
| [Volume deep features](https://rendervous.github.io/rdv_on_the_web/deep_features/) | The `VolumeDeepProfile` feature inspector: 13 per-pixel medium features (transmittance-threshold depths, reduced/effective transmittance, sun NEE, importance-sampled environment NEE, scattering albedo, interaction probability), any three shown as RGB, with the profile's ablation flags. Lit by a procedural sky. |
| [HaloRT](https://rendervous.github.io/rdv_on_the_web/halort/) | Neural volume rendering: rdv computes HaloRT's deep features on the GPU and the HaloRT network (the "ours" dir/env UNets + compose, exported to ONNX - `halort_256.onnx`/`halort_512.onnx`) runs in ONNX Runtime Web on the same WebGPU device. Needs `float32-filterable`; loads onnxruntime-web 1.30 from the jsDelivr CDN. |
| [HaloRT · directional light, clip plane](https://rendervous.github.io/rdv_on_the_web/halort_dir/) | Directional light only: the HaloRT "dir" UNet evaluated once per frame (`halort_dir_*.onnx`), no environment samples, and a clip plane on the medium (`VolumeDeepProfile.clip_direction`/`clip_distance`: only densities above the plane count, for camera and shadow rays). |

Requires a browser with WebGPU (recent Chrome/Edge; Firefox/Safari with WebGPU enabled).

## How the examples are made

Each example's `*.js` is generated by rdv's `Main.export_webgpu(...)`:

1. the node graph's megakernel GLSL is compiled to SPIR-V (glslang),
2. a lowering pass turns every `GL_EXT_buffer_reference` pointer into a byte offset into one `heap` storage buffer
   (64-bit integers are narrowed to 32 bits; memory keeps rdv's scalar layout),
3. Tint translates the result to WGSL,
4. everything reachable from the main node (node fields + data, e.g. the volume) is snapshotted into the heap, and
   the WGSL, the heap and a small WebGPU runtime are written as one ES module exposing
   `evaluate({ namedBuffer, 'field.path': value }, { threads })`.

The examples come from `src/sandbox/sandbox_webgpu_transmittance_viewer.py` and
`src/sandbox/sandbox_webgpu_radiance_viewer.py` in rdv_project, and (deep features, HaloRT)
`src/training/export_deep_features_webgpu.py`, `export_halort_webgpu.py`, `export_halort_onnx.py` and
`export_halort_dir.py` in direct_neural_rendering.

## Running locally

ES modules don't load from `file://`, so serve the folder:

```
python -m http.server 8000
```

and open http://localhost:8000.
